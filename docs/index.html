¿Qué es y para qué sirve?

El conector Tenable / Nessus permite que el agente de Ruvic consulte, en modo solo lectura, las vulnerabilidades detectadas por Tenable.io (Vulnerability Management). Una vez configurado, puedes pedirle al agente cosas como:

  • "Lista las vulnerabilidades detectadas en el activo a1b2c3d4-5678-90ab-cdef-1234567890ab."
  • "¿En qué estado está el escaneo 123? Muéstrame un resumen."
  • "Exporta los resultados del escaneo 123 en formato CSV."

Operaciones soportadas:

Operación Qué hace
security.list_vulnerabilities_by_asset Lista las vulnerabilidades detectadas en un activo (agrega los hallazgos de todos los escaneos recientes sobre ese activo)
security.get_scan Consulta el estado y resumen de un escaneo (targets, inicio/fin, hosts)
security.export_scan_results Exporta y descarga los resultados de un escaneo completado (csv, nessus, html o pdf)
Solo lectura, por diseño El conector no lanza, pausa, cancela ni elimina escaneos, y no modifica la configuración de la cuenta. Solo consulta datos ya generados y exporta resultados existentes.

Prerrequisitos

  • Una cuenta de Tenable.io (Vulnerability Management en la nube) o una instancia autoalojada compatible con la API de Tenable.
  • Acceso a Settings → My Account → API Keys en Tenable.io para generar un par de API Keys, solo durante la configuración inicial.
  • Al menos un activo o escaneo ya existente en la cuenta para poder probar la consulta (un asset_id o scan_id reales).

Configuración en el fabricante

Vas a generar un par de API Keys dedicado para Ruvic, asociado a un usuario con rol de solo lectura. No reutilices las API Keys de tu cuenta de administrador ni las de otra integración.

  1. Crea (o usa) un usuario con rol de solo lectura.

    En Tenable.io, ve a Settings → Access Control → Users y crea un usuario con rol Basic o Standard (no Administrator). Si necesitas limitar qué activos/escaneos puede ver, asígnale los Access Groups correspondientes.

  2. Genera el par de API Keys.

    Con ese usuario autenticado (o como administrador, sobre esa cuenta), entra a Settings → My Account → API Keys y pulsa Generate. Tenable muestra el Access Key y el Secret Key una única vez — cópialos de inmediato, los usarás en el formulario de Ruvic.

    Importante El Secret Key no se puede volver a consultar. Si lo pierdes, deberás regenerar el par completo (esto invalida el anterior).
    [ Captura: generación de API Keys en Settings → My Account → API Keys — reemplazar por assets/img/tenable-api-keys.png ]
  3. (Opcional) Restringe la visibilidad con Access Groups.

    Si quieres que el conector solo vea ciertos activos o escaneos, en Settings → Access Control → Access Groups crea un grupo con los activos relevantes y asígnalo al usuario del paso 1.

  4. Verifica las credenciales desde la línea de comandos.

    Con curl, confirmando que la sesión responde:

    curl -s -H "X-ApiKeys: accessKey=TU_ACCESS_KEY;secretKey=TU_SECRET_KEY" \
  https://cloud.tenable.com/session

    Si responde con un JSON de la sesión (sin error de autenticación), el fabricante quedó listo. Anota estos valores para la siguiente sección: Access Key y Secret Key.

Permisos requeridos

Principio de mínimo privilegio: el usuario dueño de las API Keys solo necesita un rol de solo lectura. No otorgues el rol Administrator ni permisos para crear, modificar, lanzar o eliminar escaneos.

Permiso Para qué sirve
Rol de usuario Basic o Standard Permite autenticarse en la API y consultar sesión, activos y escaneos visibles para ese usuario (security.list_vulnerabilities_by_asset, security.get_scan, security.export_scan_results)
Acceso a los Access Groups relevantes Limita qué activos y escaneos puede ver el conector, sin necesidad de un rol más amplio

No se requiere el rol Administrator ni permisos de escritura: el conector nunca crea, modifica, lanza ni elimina escaneos.

Configuración en Ruvic

Entra a Settings → Conectores, busca la tarjeta Tenable / Nessus y pulsa Configurar. Diligencia el formulario con los valores que obtuviste en la sección anterior:

Campo del formulario Valor
URL base Opcional; por defecto https://cloud.tenable.com. Usa la URL de tu instancia si es autoalojada
Access Key El Access Key generado en el paso 2 de la sección 3
Secret Key El Secret Key del mismo par. Se guarda cifrado como secreto: la interfaz no volverá a mostrarlo
Timeout de conexión Opcional; 15 segundos por defecto

Guarda y pulsa Probar conexión — la plataforma consultará la sesión actual en Tenable y confirmará que las credenciales funcionan.

[ Captura: formulario del conector Tenable / Nessus en Settings → Conectores — reemplazar por assets/img/tenable-form.png ]

Verificación

  1. Test de conexión exitoso.

    El botón Probar conexión debe responder: "Conexión exitosa a Tenable (https://cloud.tenable.com)". La tarjeta del conector cambia a estado Configurado.

  2. Automatización mínima de prueba.

    Abre una conversación nueva con el agente y pídele: "Lista las vulnerabilidades detectadas en el activo <asset_id>." (usa un asset_id real de tu cuenta). El agente debe responder con la lista real de vulnerabilidades (plugin, severidad, cantidad). Si lo hace, el conector quedó operativo de punta a punta.

Solución de problemas

Mensaje / síntoma Causa probable y solución
"Autenticación fallida: Credenciales inválidas o sin permiso suficiente para esta operación." El Access Key o el Secret Key están mal copiados, o el par fue revocado. Reintenta el paso 2 de la sección 3, genera un par nuevo si hace falta y vuelve a guardar el formulario.
"Error de red: No se pudo alcanzar Tenable en '...'" Timeout o problema de red hacia Tenable. Verifica que la URL base sea correcta (sin ruta ni barra final), que no haya un firewall bloqueando la salida, y considera aumentar el timeout de conexión.
"El activo/escaneo solicitado no existe." asset_id o scan_id mal escrito, o el usuario de las API Keys no tiene visibilidad sobre ese activo/escaneo por sus Access Groups. Verifica el identificador y los grupos de acceso del paso 3 de la sección 3.
La exportación del escaneo no termina ("no terminó en 60s") Tenable tarda en preparar archivos de exportación grandes; el conector espera hasta 60 segundos. Reintenta más tarde o exporta un escaneo con menos hallazgos. Verifica primero con get_scan que el estado sea completed.
El conector aparece "Sin configurar" tras guardar Falta el Access Key o el Secret Key (son obligatorios). Ábrelo de nuevo y completa ambos campos; la URL base y el timeout son opcionales.

Preguntas frecuentes y notas de seguridad

¿El agente puede lanzar, pausar o eliminar escaneos?

No. La librería del conector es de solo lectura: solo expone list_vulnerabilities_by_asset, get_scan y export_scan_results. No existe ninguna operación para crear, modificar, lanzar, pausar ni eliminar escaneos, aunque el usuario de las API Keys tuviera permisos para ello.

¿Dónde queda guardado el Secret Key?

Como secreto en el almacén de credenciales de la plataforma, asociado a tu usuario. La interfaz nunca vuelve a mostrarlo; solo indica "definido". Para cambiarlo, escribe uno nuevo en el formulario; para conservarlo al editar otros campos, deja el campo vacío.

Rotación de credenciales

Recomendado cada 90 días o según tu política: genera un par nuevo de API Keys en Settings → My Account → API Keys, actualízalo en el formulario del conector, pulsa Probar conexión y luego revoca el par anterior desde Tenable.

¿Qué hago si las API Keys se comprometen?

  1. Revoca el par de API Keys de inmediato en Tenable.io: Settings → My Account → API Keys → Revoke.
  2. Revisa los logs de auditoría de la cuenta Tenable para detectar actividad reciente asociada a ese usuario.
  3. Genera un par nuevo y actualízalo en el formulario del conector.

¿Expiran las API Keys?

Por defecto no (las API Keys de Tenable no caducan solas). Si tu política exige expiración o rotación forzosa, gestiona un calendario de rotación manual como el descrito arriba.

Buenas prácticas Usa siempre un par de API Keys dedicado y de solo lectura (rol Basic o Standard, nunca Administrator); restringe la visibilidad con Access Groups al mínimo necesario; y evita compartir el Secret Key por canales no seguros.
